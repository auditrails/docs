# Authentication

All AuditRails API requests require a **Bearer token** in the `Authorization` header.

## API Key Format

```
at_live_xxxxxxxxxxxxxxxxxxxxxxxx   # Production key
at_test_xxxxxxxxxxxxxxxxxxxxxxxx   # Test key (free, no quota)
```

## Using Your API Key

### With an SDK

Pass the key when initializing the client:

<CodeGroup>

```typescript Node.js
const audit = new AuditRails({ apiKey: process.env.AUDITRAILS_API_KEY });
```

```python Python
audit = AuditRails(AuditRailsConfig(api_key=os.environ['AUDITRAILS_API_KEY']))
```

```go Go
client, _ := auditrails.New(os.Getenv("AUDITRAILS_API_KEY"), auditrails.Options{})
```

```php PHP
$audit = new AuditRails(new Config(apiKey: env('AUDITRAILS_API_KEY')), ...);
```

```java Java
AuditRails audit = AuditRails.builder(System.getenv("AUDITRAILS_API_KEY")).build();
```

</CodeGroup>

### With curl

```bash
curl -X POST https://api.auditrails.io/v1/events \
  -H "Authorization: Bearer at_live_..." \
  -H "Content-Type: application/json" \
  -d '{"action": "user.login", "actor_id": "user_123"}'
```

## Generating API Keys

1. Go to **Dashboard → API Keys**
2. Click **Create API Key**
3. Name the key (e.g., "Production Backend")
4. Copy the key immediately — it's only shown once

<Warning>
API keys are shown only once at creation. If you lose a key, revoke it and create a new one.
</Warning>

## Security Best Practices

- **Never commit API keys** to source control — use environment variables
- **Use separate keys** for each environment (production, staging, development)
- **Use test keys** (`at_test_...`) for development — they're free and don't affect quotas, but they also draw from a separate, much smaller rate-limit pool (60 req/s by default), so don't use one for load testing or production traffic
- **Rotate keys** periodically — revoke old keys and create new ones
- **Restrict access** — only team admins and members can create/revoke keys

## Key Storage

AuditRails never stores your raw API key. When you create a key:

1. The raw key is generated and shown to you once
2. A SHA-256 hash of the key is stored in our database
3. When you make an API request, we hash the provided key and compare it

This means if our database were ever compromised, your keys would not be exposed.

## Error Responses

Invalid or missing authentication returns a `401 Unauthorized` response:

```json
{
  "error": {
    "code": "auth/key_not_found",
    "message": "API key not found. Verify the key is correct or generate a new one in the dashboard.",
    "request_id": "req_01HX...",
    "doc_url": "https://docs.auditrails.io/reference/error-codes"
  }
}
```

See [Error Codes](/reference/error-codes) for the full list — `auth/missing_header`, `auth/invalid_format`, `auth/key_not_found`, `auth/key_revoked`, and `auth/key_expired` are all possible here.
